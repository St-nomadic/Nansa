# NANSA — 채용공고 맞춤형 지원 서류 자동 생성 및 관리 서비스

Manyfast 프로젝트 **"채용공고 맞춤형 지원 서류 자동 생성 및 관리 서비스"** (PRD + 요구사항 6개 / 기능 27개 / 스펙 57개)를 참고하여, 업로드된 NANSA 스탠드얼론 목업(Wanted Design System 토큰)을 실제 동작하는 웹 앱으로 구현한 MVP입니다.

> **목업 → 구현 차이**: 목업은 로그인/홈/공고/공고상세/생성 5개 화면만 있고 데이터·로직이 하드코딩된 프로토타입이었습니다. 이 구현은 목업의 디자인 시스템과 화면 구조를 그대로 계승하면서 ① 내비게이션에만 존재하던 **내 프로필 / 내 서류 / 최종 점검·제출 / 지원 관리** 화면을 완성하고 ② 가짜였던 JD 분석·문서 생성·내보내기·저장을 **실제 동작하는 규칙 기반 엔진**으로 대체했습니다.

## 실행 방법

빌드 도구가 필요 없습니다.

```bash
# 방법 1: 브라우저에서 index.html 을 바로 열기
# 방법 2: 정적 서버
python3 -m http.server 8080
# → http://localhost:8080
```

- 모든 데이터는 브라우저 `localStorage`(`nansa.v1`)에 저장됩니다. 초기화하려면 개발자 도구에서 해당 키를 삭제하세요.
- 로그인 화면은 데모 인증입니다(아무 값으로나 로그인 진입).

## 테스트

```bash
node tests/run-tests.js   # 24개 단위 테스트 (JD 분석기 + 문서 생성기)
```

브라우저 E2E는 Playwright + Chromium 스모크 테스트로 검증했습니다(로그인 → 공고 등록/JD 분석 → 이력서 생성 → AI 보정/되돌리기 → 체크리스트 → 지원 기록 → 스냅샷 잠금 → 새로고침 영속성, 24개 체크 전부 통과).

## 구조

```
├── index.html          앱 셸 (빌드 없이 <script> 로드)
├── css/
│   ├── tokens.css      목업에서 계승한 Wanted DS 디자인 토큰
│   └── app.css         컴포넌트 스타일
├── js/
│   ├── data.js         시드 데이터 (첫 실행 시에만 사용)
│   ├── jd.js           JD 분석기 — 섹션 구조화 / 스킬 사전 매칭(별칭 정규화) / 중요도 산정 / 시니어리티·마감일·회사명 추정
│   ├── generator.js    문서 생성기 — 이력서·자소서·포트폴리오 템플릿, 톤/길이/언어/강조 설정, 매칭 근거, 커버리지, 규칙 기반 보정, 파일명 규칙
│   ├── exporter.js     내보내기 — PDF(인쇄), DOCX(워드 호환 .doc), 클립보드 복사
│   ├── store.js        단일 스토어(SOT) + localStorage 영속화 + 문서 undo/redo + 프로필 변경 이력
│   ├── views.js        상태 → HTML 렌더러 (9개 화면 + 3개 모달)
│   └── app.js          이벤트 위임 컨트롤러 + 렌더 루프(포커스 보존)
└── tests/run-tests.js  Node 단위 테스트
```

### MVP 범위 제한 (의도적)

- **백엔드 없음**: 인증·데이터는 로컬 데모. 실제 서비스화 시 API 계층으로 교체 지점은 `store.js` 하나로 수렴되어 있습니다.
- **URL 공고 파싱(S-LITJIB)**: 브라우저 CORS 제약으로 원격 파싱은 불가 → 공고 셸 등록 후 본문 붙여넣기 폴백으로 구현.
- **AI 보정/생성**: LLM 미연동, 결정적 규칙 기반. 인터페이스(`generator.js`)는 LLM 교체를 전제로 분리되어 있습니다.
- **PPTX 내보내기(S-YVVFWV)·공유 링크(S-XXEVHZ)·마감 알림(S-DEQSYM)**: 미구현(후속 범위). 내보내기는 PDF/DOCX/복사로 R-DXIZND 수락 기준(최소 1개 형식)을 충족합니다.
